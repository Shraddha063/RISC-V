## Overview

Day 1 focused on understanding the RISC-V toolchain, compiling and executing C programs, examining the generated RISC-V assembly code, and debugging program execution using the Spike RISC-V ISA Simulator.

## 1. Sum of Numbers from 1 to 10

### C Program

The first program calculates the sum of integers from 1 to 10 using a `for` loop.

```c
#include <stdio.h>

int main()
{
    int i, sum = 0;
    int n = 10;

    for (i = 1; i <= n; i++)
    {
        sum = sum + i;
    }

    printf("Sum of numbers from 1 to %d is %d\n", n, sum);

    return 0;
}
```

### Native Compilation and Execution

Compiled and executed the program using the native GCC compiler:

```bash
gcc sum1ton.c -o sum1ton
./sum1ton
```

**Output:**

```text
Sum of numbers from 1 to 10 is 55
```

## 2. RISC-V Cross Compilation

Used the RISC-V GCC cross-compiler to generate assembly code for the program.

```bash
riscv64-unknown-elf-gcc -Ofast -mabi=lp64 -march=rv64imac -S sum1ton.c -o sum1ton_Ofast.s
```

Generated assembly files using different optimization levels:

- `sum1ton_O0.s`
- `sum1ton_O2.s`
- `sum1ton_Ofast.s`

### Comparing Optimization Levels

Compared the assembly generated with `-O0` and `-O2`:

```bash
diff -u sum1ton_O0.s sum1ton_O2.s
```

The comparison showed that:

- **O0:** The compiler retained the loop and generated instructions for stack-based variable handling and loop execution.
- **O2:** The compiler optimized the program by calculating the result at compile time. The loop was eliminated.
- **Ofast:** For this program, the generated assembly was identical to the `-O2` output.

## 3. RISC-V Assembly and Disassembly Analysis

Inspected the generated assembly and disassembled the executable to understand the instructions generated by the compiler.

```bash
riscv64-unknown-elf-objdump -d sum1ton_O0.o
```

The `main` function begins at address `0x10158` in the inspected executable.

Some instructions observed:

| Instruction | Description |
|---|---|
| `addi` | Adds an immediate value to a register |
| `sd` | Stores a doubleword in memory |
| `sw` | Stores a word in memory |
| `lw` | Loads a word from memory |
| `addw` | Performs 32-bit addition |
| `addiw` | Adds an immediate to a 32-bit value |
| `ble` | Branches if less than or equal |
| `call` | Calls a function |
| `jr` | Jumps to the address in a register |

The disassembly helped correlate the C program with its corresponding RISC-V instructions.

## 4. Execution Using Spike RISC-V ISA Simulator

Executed the RISC-V program using Spike and the proxy kernel (`pk`).

```bash
spike --isa=rv64imac /home/vsduser/riscv_workshop_collaterals/riscv_toolchain/riscv-pk/build/pk sum1ton.o
```

**Output:**

```text
bbl loader
Sum of numbers from 1 to 10 is 55
```

This verified that the cross-compiled RISC-V executable runs successfully on the Spike simulator.

## 5. Debugging Using Spike

Started Spike in debug mode:

```bash
spike -d pk sum1ton.o
```

Used the Spike debugging prompt to inspect processor registers and the program counter.

Commands used:

```text
reg 0 sp
reg 0 ra
reg 0 a0
reg 0 a1
reg 0 a2
pc 0
```

The `reg` command was used to inspect register values, while `pc` displayed the current program counter.

The following observations were made:

- `sp` – Stack pointer
- `ra` – Return address
- `a0`–`a7` – Argument and return-value registers
- `pc` – Program counter

The `until pc` command can be used to run the simulator until a specified program counter address is reached.

## 6. Signed Integer Limits in C

Created a C program using the `limits.h` header to examine the maximum and minimum values of a signed integer.

### C Program

```c
#include <stdio.h>
#include <limits.h>

int main()
{
    printf("Highest Number is %d\n", INT_MAX);
    printf("Lowest Number is %d\n", INT_MIN);

    return 0;
}
```

### RISC-V Compilation

```bash
riscv64-unknown-elf-gcc -O1 -mabi=lp64 -march=rv64i -o signedHighest.o signedHighest.c
```

### Execution Using Spike

```bash
spike pk signedHighest.o
```

**Output:**

```text
bbl loader
Highest Number is 2147483647
Lowest Number is -2147483648
```

Although the target architecture is RV64, the C `int` data type is 32 bits under this ABI.

| Constant | Value |
|---|---:|
| `INT_MAX` | 2147483647 |
| `INT_MIN` | -2147483648 |
